# CLI и локальное извлечение

## CLI прогонов

Нужен Node 24 и установленные зависимости `web`. Каталог запрашивает работающий
Hono с Python из настроенного окружения. Команда выполняется без PDF, RabbitMQ
и Python-воркера.

```bash
./rag strategies
./rag strategies --json
```

`GET /api/strategies` отдаёт зарегистрированные ридеры в группах `text`,
`table` и `figure`. Табличные ридеры сообщают, требуется ли ручной `crop` и
можно ли передать адрес области из карты. Для графиков в JSON есть
`parameters_schema`. Применимость к конкретному PDF, доступность моделей и
настройки полного прогона проверяются при выборе ридера и выполнении.

Для прогонов поднимите
[Hono, RabbitMQ и Python-воркер](../web/README.md#разобрать-статью-через-rabbitmq).
Запускайте команды из корня репозитория.

```bash
./rag run ./D001.pdf --out runs/d001
./rag compare ./D001.pdf --figure 5 \
  --figure-reader vector-bar --figure-reader vector-line --jobs 1 \
  --out runs/d001-figure5-compare
```

Вместо пути можно указать ID статьи в Hono или прямую HTTPS-ссылку на PDF
без редиректов.
`--base-url` выбирает сервер (по умолчанию `http://127.0.0.1:4310`).
В `run` ридеры задаются флагами `--table-reader`, `--text-reader`,
`--figure-reader`; пропущенные этапы используют `auto`. Для одного рисунка
укажите `--figure` с меткой или ID кандидата карты. Параметры графического
ридера можно передать в JSON через `--parameters-file`. В сравнении
этот файл применяется ко всем выбранным ридерам рисунка, и каждый ридер
проверяет его по своей схеме.

Явный табличный ридер используется без смены стратегии. Если он требует
ручного `crop` или не поддерживает обнаруженные области, команда вернёт
причину до постановки в очередь. При отсутствии рисунка в карте скана
`--figure` сообщит об этом. Для ручного адреса используйте диагностику
`python -m rag_mvp.plot_extract --help`.

В `compare` повторите флаг ридера одного этапа. Каждая стратегия получает
отдельный прогон с одинаковой версией PDF и остальными входами.
`--jobs 1` (по умолчанию) ждёт завершения одного прогона перед следующим.
При сравнении результаты сохраняются локально без публикации в библиотеку.
Обычный полный `run` применяет штатную настройку публикации Hono.

В `--out` находятся `manifest.json` для `run` или `comparison.json` для
`compare`. В них есть ID и статус каждого прогона и путь к его артефактам.
В каждом варианте `reconciliation.json` хранит результаты, замечания, источники
и выбранный контекст. При публикации из того же итога собираются паспорт,
веб-представление и ZIP с CSV. По истечении `--wait-seconds`
клиент прерывает ожидание и сохраняет уже полученный ID. Для продолжения
запустите ту же команду с тем же `--out`. После принудительного завершения
(`SIGKILL`) можно удалить `.rag-lock` в этом каталоге, убедившись, что
другой экземпляр CLI его не использует.

Если автоматические попытки упаковки исчерпаны, отправьте
`POST /api/article-runs/<run-id>/publication/retry`. Hono возьмёт сохранённый
итог этого прогона и снова запустит упаковку.

В `article-context.json` сохраняются фрагменты и основания привязки выбранной
таблицы или рисунка. Табличную привязку можно повторить по сохранённой сетке и
подборке в новый каталог:

```bash
python -m rag_mvp extract ./D009.pdf --page 5 --table 1 \
  --grid-input table-grid.json --context-input article-context.json --out runs/d009-repeat
```

Укажите стратегию и область из исходного прогона, если они были заданы. Для
рисунка флаг `--context-input` команды `read-article-figure` использует прежнюю
подборку с той же картой статьи.

### PaddleOCR для сканов

`paddle-structure` доступен через явный `--table-reader` для подтверждённых
областей таблиц. Воркер растрирует исходную страницу и передаёт локальный
PNG в PP-StructureV3. Для Paddle используется отдельное Python-окружение.

```bash
python3 -m venv runs/paddle-venv
runs/paddle-venv/bin/python -m pip install -r requirements-paddle.txt
export RAG_PADDLE_PYTHON="$PWD/runs/paddle-venv/bin/python"
export PADDLE_PDX_CACHE_HOME="$PWD/runs/paddle-model-cache"
```

Передайте эти переменные процессу Python-воркера. Первый запуск скачивает
веса моделей. Распознавание идёт локально на CPU.

Чтобы Auto мог использовать Paddle как запасной ридер, задайте
`RAG_PADDLE_PYTHON` также серверу. После Docling с OCR и TableFormer воркер
использует этот резерв для подтверждённой области, где есть дефект одиночной
ячейки и опоры для проверки её строки и столбца. Запасная попытка входит в
существующий лимит этапа.

```bash
./rag compare ./D021.pdf --table-reader docling-ocr-tableformer \
  --table-reader paddle-structure --jobs 1 --out runs/d021-paddle
```

Оба варианта используют исходные области таблиц из одной карты статьи.
Сырые OCR-токены, HTML и рамки Paddle сохранены внутри `table-grid.json`.
К публикации допускаются только значения, прошедшие общую проверку
положения ячейки и её условий. Смещённые или спорные источники видны в замечаниях.

### Локальный Qwen

Для рисунков и предложений по условиям таблиц достаточно одной модели.
Запустите Ollama и передайте его адрес в окружении Python через
`RAG_OLLAMA_URL`. При прямом запуске на одном хосте по умолчанию
используется `127.0.0.1:11434`. При запуске в Compose укажите адрес Ollama, доступный из контейнера воркера.

```bash
ollama pull qwen3-vl:4b-instruct-q4_K_M
ollama list
./rag run ./D001.pdf --figure 5 --figure-reader qwen-vision --out runs/d001-qwen-figure
python -m rag_mvp propose-table-conditions --help
```

Qwen для условий таблиц запускается отдельным экспериментом по сохранённым
фрагментам текста. Параметры вызова показывает `python -m rag_mvp propose-table-conditions --help`.
Оба сценария делят один слот на Linux при запуске от одного пользователя
в общей среде и выгружают модель после запроса. Можно отдельно переопределить
модель через `RAG_QWEN_MODEL` для графиков на воркере и
`RAG_QWEN_TEXT_MODEL` для текстовой команды. Для первого вызова модели
можно увеличить таймаут до 90 секунд через `RAG_QWEN_TIMEOUT_SECONDS`
в окружении Python-воркера или текстовой команды.

## Запуск MVP на D001

Распакуйте комплект участника по [инструкции](context/viniti.md). Команды ниже запускаются из корня репозитория с Python 3.12. Первый запуск Docling скачивает веса для разбора страницы и таблицы. Для установки PyTorch на CPU сначала используйте его CPU-индекс.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt

run_dir="$(mktemp -d)/d001"
python -m rag_mvp extract 'docs/context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D001.pdf' \
  --page 6 --table 1 --out "$run_dir"
python -m rag_mvp serve "$run_dir"
```

Откройте адрес, который напечатает `serve`. Выберите датасет и нажмите на значение, чтобы увидеть его место в PDF. В каталоге прогона лежат `results.csv`, `run.json`, исходный JSON Docling и локальная копия PDF.

## Скан D013

```bash
corpus="$PWD/docs/context/RAG_ВИНИТИ_участникам_2026-11-20"
run_dir="$(mktemp -d)/d013"
python -m rag_mvp extract "$corpus/dev/D013.pdf" \
  --page 6 --table 2 --strategy docling-rapidocr --out "$run_dir"
python -m rag_mvp serve "$run_dir"
```

В «Прочитанной сетке» доступны заголовки, ячейки и подтверждающие абзацы со страницы 7. Среднее и SD открывают один OCR-фрагмент на странице 6. В «Данных прогона» можно открыть параметры и сырые выгрузки движка.

## Цифровая таблица D008

```bash
corpus="$PWD/docs/context/RAG_ВИНИТИ_участникам_2026-11-20"
run_dir="$(mktemp -d)/d008"
python -m rag_mvp extract "$corpus/dev/D008.pdf" \
  --page 14 --table 4 --strategy pdfplumber --crop 75 70 285 144 --out "$run_dir"
python -m rag_mvp serve "$run_dir"
```

Область задаётся в пунктах PDF от верхнего левого угла страницы в порядке `X0 TOP X1 BOTTOM`. Нажмите на число в «Прочитанной сетке», чтобы открыть ячейку на странице 14. В «Данных прогона» доступны координаты области и исходная выгрузка pdfplumber. Генератор, датасет, оборудование и длина генерации для этих измерений неизвестны. Значения в секундах доступны в сетке, а `results.csv` содержит только заголовки.

Предметные проверки запускаются командой `python -m unittest discover -s tests -v`. Чтобы проверить штатные прогоны на PDF комплекта и сверить JSON и CSV, запустите `RAG_DEV_CORPUS="$corpus" python -m unittest discover -s tests -v`.
