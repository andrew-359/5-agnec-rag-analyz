# Навыки Matt Pocock для проекта RAG

В чате Codex, открытом в RAG, напиши `$название-навыка` и задачу. Можно выбрать один навык под текущий вопрос. Для мелкой правки достаточно обычного запроса.

## Самые полезные для нас

| Навык | Когда брать | Пример запроса |
| --- | --- | --- |
| `$prototype` | Есть ощущение, что интерфейс неудобен, но пока сложно объяснить, как его переделать. Быстро даёт несколько вариантов для сравнения. | «Покажи оглавление по разделам и ленту страниц на одном PDF. Только десктоп». |
| `$grill-with-docs` | Нужно принять спорное решение и сохранить термины или причины выбора. Лучше ограничить обсуждение одним вопросом. | «Обсудим только то, как пользователь с карты попадает к конкретному числу». |
| `$diagnosing-bugs` | Видим ошибку, зависание или странный результат. Сначала ищет короткий способ поймать симптом, затем проверяет причину. | «Почему на P002 у таблицы нет значений? Проверь подпись, сетку и правила извлечения по очереди». |
| `$research` | Надо выбрать готовую библиотеку или проверить, что она умеет. Результат — Markdown с выводами и первичными источниками. | «Сравни pdfplumber и текущий Docling для таблиц с объединённой шапкой. Укажи, что проверить на наших PDF». |
| `$to-spec` | Уже договорились о поведении и хотим зафиксировать его для реализации. | «Запиши, как работает переход от таблицы в карте к ячейке и как это проверить». |
| `$to-tickets` | Согласованную работу нужно разбить на небольшие задачи, каждую из которых можно показать отдельно. | «Разбей новый вид карты на короткие задачи с зависимостями. Первая должна работать на одном реальном PDF». |
| `$tdd` | Ошибка легко повторяется и важна защита от повторения. Сначала проверка, которая падает на баге, потом исправление. | «Зафиксируй, что повторный запрос на ту же таблицу не запускает второй разбор». |
| `$code-review` | Есть ветка или коммит и нужно сверить реализацию с задачей и правилами репозитория. | «Проверь изменения после 4285107. Особое внимание — очередь и связь результатов с исходным PDF». |
| `$handoff` | Нужно передать работу другому разработчику или продолжить в новой сессии. | «Запиши, что уже принимает API, что проверить в CLI и где лежит прогон D001». |
| `$ask-matt` | Непонятно, какой навык взять. | «Хотим быстро сравнить два способа навигации по статье. Какой навык подойдёт?» |

## Как я бы применил к карте статьи

1. **Одна короткая итерация с `$prototype`.** На одном и том же PDF сравнить оглавление по разделам и ленту страниц. Проверить один сценарий — найти таблицу, открыть результаты и перейти к числу в PDF.
2. **Выбрать один вариант или смешать конкретные элементы.** Если остался спорный вопрос, обсудить его через `$grill-with-docs`.
3. **Взять один кусок в реализацию.** Например, сначала сгруппировать таблицы по разделам и сохранить переход к подписи. `$to-spec` и `$to-tickets` нужны, когда решений уже несколько и их предстоит передавать или делать в разных итерациях.

## Остальные установленные навыки

| Навык | Для чего |
| --- | --- |
| `$grill-me`, `$grilling` | Разобрать идею или решение через вопросы. `grill-me` можно взять и для темы вне кода. |
| `$domain-modeling` | Уточнить термины команды, обновить глоссарий или зафиксировать архитектурное решение. |
| `$codebase-design` | Продумать границы модулей и их интерфейсы. |
| `$improve-codebase-architecture` | Найти проблемы в устройстве существующего кода и обсудить, какой рефакторинг даст пользу. |
| `$implement` | Реализовать конкретную спецификацию или набор задач. |
| `$implement-spec` | Довести крупную спецификацию с зависимыми задачами до интеграционной ветки. |
| `$triage` | Разобрать накопившиеся задачи, уточнить их и отметить готовые к работе. |
| `$wayfinder` | Составить карту решений для работы, которая не помещается в одну сессию. |
| `$pr` | Написать описание PR по фактическим изменениям. |
| `$retro` | Разобрать, что затянуло итерацию и как сократить следующую. |
| `$setup-matt-pocock-skills` | Настроить трекер, метки и расположение документов. Для RAG уже настроено. |
| `$teach`, `$wait-what` | Разобраться в новой теме или переформулировать объяснение, которое было непонятно. |
| `$to-questionnaire` | Подготовить вопросы для человека, у которого есть недостающая информация. |
| `$wizard` | Подготовить инструкции для шагов, которые может выполнить только человек. |
| `$writing-for-agents` | Написать или уточнить инструкции для агентов, например `AGENTS.md` или `SKILL.md`. |

Проект хранит спецификации и задачи в [`.scratch/`](../../.scratch/). Настройки описаны в [`AGENTS.md`](../../AGENTS.md), термины — в [`GLOSSARY.md`](../../GLOSSARY.md). Назначение навыков сверено с установленной копией [mattpocock/skills](https://github.com/mattpocock/skills/tree/abeeaf95660ba9e8b7c753eb38f441ca707a8823).
