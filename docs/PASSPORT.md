# Паспорт данных RAG

Черновик на одной статье D001 (ThreadRAG). Значения сверены с PDF, идентификаторы взяты из разметки `dev_gold`. При выпуске `PASSPORT.md` кладём рядом с семью CSV и сверяем примеры с этой версией выгрузки.

**Охват примера — D001, Table 1 и Table 2 (страницы 6–7 PDF).** В паспорте выпуска здесь указываем фактический охват выгрузки. Пропуски, спорные записи и причины описываем в отчёте проверок.

## Быстрый старт

**EM = 0,422** для ThreadRAG с LLaMA3-8B-Instruct на HotpotQA. В `results.csv` из эталона это `D001 / R235`. Одна строка хранит одно измерение одной метрики для конкретного эксперимента, конфигурации, набора и задачи.

1. В `results.csv` найдите `publication_id = D001` и `result_id = R235`. `raw_value` хранит напечатанное `.422`, нормализованная запись — `0.422` в долях. Символ единицы рядом с числом в таблице не напечатан, поэтому `raw_unit` пуст.
2. По `D001 / E1` в `experiments.csv` найдите протокол основной оценки. По `D001 / C40` в `configurations.csv` найдите конфигурацию. ID эксперимента и конфигурации ищем вместе с ID публикации.
3. Откройте PDF на странице 6, Table 1. Строка `ThreadRAG`, шапка `LLaMA3-8B-Instruct → HotpotQA → EM`. Настройка поиска `top_k = 5` описана в §4.1. [D001, страница 6](context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D001.pdf#page=6)

**Почему есть ещё одно `.422`?** `D001 / R257` относится к полной конфигурации в эксперименте с отключением компонентов (`E2`), страница 7, Table 2, столбец `HotpotQA`. У двух записей свои эксперименты и свои ячейки. В той же таблице `.238 (↓ 18.4%)` даёт две записи из одной ячейки: EM `0.238` и снижение `18.4` процентного пункта. Исходную запись снижения сохраняем, а нормализованную шкалу обосновываем разностью `(0.422 − 0.238) × 100`. [D001, страница 7](context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D001.pdf#page=7)

## Справочник метрик

В D001 авторы нормализуют текст предсказанного и эталонного ответов перед вычислением EM и F1. Чтобы сравнивать числа из разных экспериментов, сверяйте задачу, набор и выборку, вариант метрики и протокол. [D001, §4.1](context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D001.pdf#page=6) · [Правила сопоставления](submission-contract.md#что-требует-кейс)

| Метрика | Что измеряет в D001 | Шкала и направление | Пример |
| --- | --- | --- | --- |
| **EM (Exact Match)** | Доля ответов, которые точно совпали с эталоном после нормализации текста. | Доля от 0 до 1. Больше — лучше. | `D001 / R235`, `.422` → `0.422`. |
| **F1** | Совпадение на уровне токенов. Учитывает, какая часть токенов ответа совпала с эталоном и какая часть эталона нашлась в ответе. | Доля от 0 до 1. Больше — лучше. | `D001 / R236`, `.513` → `0.513`, соседний столбец F1 в той же строке. |

## Где искать остальные поля

- `publications.csv` — статьи и решение о включении в набор.
- `configurations.csv`, `datasets.csv`, `tasks.csv`, `experiments.csv` — как получено измерение и в каких условиях.
- `results.csv` — измерения, исходные и нормализованные значения, адреса источников.
- `issues.csv` — замечания с правилом, затронутыми записями и местом в PDF.

Пустое поле означает, что значение не указано или не подтверждено. Числовой ноль сохраняется как `0`. `top_k` описывает настройку поиска, `metric_k` — отсечку метрики вроде `Recall@10`. Полные имена полей, связи и правила сверяйте с [контрактом сдачи](submission-contract.md#семь-файлов-экспорта).
