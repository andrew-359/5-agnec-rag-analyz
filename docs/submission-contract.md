# Контракт сдачи ВИНИТИ, область 2

Сверено 21 ноября 2026 года по [презентации](context/ВИНИТИ+ЮФУ.pdf#page=7) и распакованному комплекту участника. Имена и порядок полей взяты из [schema.json](context/RAG_ВИНИТИ_участникам_2026-11-20/submission_template/schema.json).

## Что требует кейс

| Страницы PDF | Требование |
| --- | --- |
| 2, 7 | Извлекать объекты, показатели, условия и результаты. Трек 2 охватывает системы, которые ищут во внешней коллекции документов и используют найденный контекст в ответе. Включаются публикации с описанием конфигурации и результатами оценки. |
| 8 | Публикация, конфигурация поиска и генерации, набор, задача и эксперимент. Сохраняются параметры, указанные в статье. |
| 9 | Результат метрики связан с публикацией, конфигурацией, датасетом, задачей и экспериментом. Сохраняются происхождение, указатель в PDF, исходная и нормализованная запись, статус. Сопоставимость требует совпадения задачи, набора, определения метрики и протокола. Разные эксперименты остаются отдельными записями. |
| 10 | Проверять шкалу, определение, направление улучшения, cutoff @k, связи и согласованность. Нормализовать при установленной шкале. При нарушении сохранить результат и добавить замечание с правилом, записью и источником. |
| 11 | Сдать машиночитаемый набор со связями, паспорт полей/типов/размерностей/правил, интерфейс с поиском/фильтрами/источником/проверками и результаты проверок с причинами. Оценивают по эталону и независимым примерам. |

Презентация не задаёт HTTP API, форму ответа LLM, точный JSON, обязательный веб-аплоад, веса метрик оценки или обязательную технологию обработки. Комплект предлагает семь CSV для машинной сверки, прямо отмечая, что это адаптация, а не официальный обязательный шаблон RAG. Для нашего экспорта это проверяемый целевой формат. Внутреннее представление приложения может хранить более точные источники и дополнительные связи.

## Что считать заполненной записью

- `publications.csv` содержит каждый PDF проверяемого набора. Для исключённой публикации нужны `in_scope=false` и причина. В остальных таблицах строк по ней нет. Исключение по теме отличается от сбоя обработки.
- Одна строка результата — одно значение одной метрики в одном эксперименте, для конкретной конфигурации, датасета и задачи. `E1` у двух статей не означает общий эксперимент. Разные разбиения, варианты метрик, методы и прогоны не сливаются по имени.
- Для результатов качества оценщика `generator_model` сохраняет только генератор ответов, подтверждённый статьёй. Подтверждённую модель-судью записываем в `configurations.csv` в `note` с явным указанием роли. При сверке с dev-эталоном учитываем, что в D021 его разметчики сохранили судью в `generator_model` с пояснением. [Пример в эталоне](context/RAG_ВИНИТИ_участникам_2026-11-20/dev_gold/configurations.csv#L4729)
- `top_k` относится к поиску, `metric_k` — к метрике @k. Дробный порог вида `OC@0.8` не является retrieval cutoff. Ноль сохраняется как число, а отсутствующее значение — пустая ячейка. Неизвестные версии и параметры не достраиваются. Диапазон не превращается в среднее.
- `raw_value/raw_unit` сохраняют исходную запись и напечатанную единицу, если она есть. `normalized_value/normalized_unit` отражают обоснованную нормализацию и согласуются с `metric_value/metric_unit`. Долю, проценты, процентные пункты, относительное изменение, BLEU/ROUGE и время нельзя пересчитывать по названию. `baseline_value` заполняется только для сопоставимого baseline.
- `sample_size` — число наблюдений оценочной выборки. Размер всего датасета или число повторных запусков имеют другой смысл. Задержку и токены, зависящие от конфигурации, лучше оформить как связанные результаты, чем распространять на весь эксперимент.
- У извлечённого результата обязательны `metric_name`, статус, происхождение, `raw_value`, `source_page` и один из `source_fragment/source_table/source_figure`. Пропуск числового `metric_value` и незаполненные четыре связи у извлечённого `primary` вызывают предупреждения валидатора. Это техническая терпимость, а не разрешение терять известный контекст.
- `source_page` — страница PDF с 1. `source_fragment` — дословный фрагмент с этой страницы. Уточнение строки/столбца, метод чтения графика и его точность можно писать в `note`. В шаблоне нет bbox и списка отдельных источников для каждого поля. Для веб-просмотра имеет смысл сохранять их внутри системы.
- `primary` включает baseline, который авторы запустили сами. `cited` требует идентификатор цитаты из статьи, например `[12]`. Это не внешний ключ на другую строку `publications.csv`. Происхождение определяем для числа.
- `extracted` — значение извлечено, `present_not_extractable` — источник указывает на значение, которое нельзя достоверно извлечь, `absent` — обоснованный случай отсутствия. Пропуск поля, сбой обработки и отсутствие результата различаются. Искусственно добавлять строки для всех комбинаций не надо.
- Повтор получает собственный `result_id`, ссылку `duplicate_of` на основную запись той же публикации и собственный источник. Если числа расходятся, сохраняем обе записи и замечание. Валидатор допускает совместимое округление дублей при совпадении остальных проверяемых полей.
- В `issues.csv` указываем правило, причину, затронутые `record_ids` через точку с запятой и источник. Поля `in_scope`, `exclusion_reason`, `duplicate_of`, `note` и структура замечаний — соглашения шаблона. Типы и правила для фактического экспорта нужно описать в паспорте.

## Проверка и примеры

- CSV в UTF‑8, разделитель запятая, десятичный знак точка. Пустые ячейки не подменяются строками `null`, `unknown` или `NaN`. Имена и порядок колонок должны совпасть со схемой. Булевы значения, происхождение и статус имеют закрытые словари в шаблоне; направления улучшения рекомендованы, остальные предметные примеры открыты.
- `python tools/check_submission.py submission test --json-report report.json` из корня комплекта. С флагом `--ocr` и локальным Tesseract проверяются цитаты страниц без текста. Ненайденная цитата, один визуальный указатель или недоступный OCR требуют проверки. Коды: 0 — выполненные проверки пройдены, 1 — ошибки, 2 — предупреждения или нерешённые проверки. Отдельно оцениваем полноту, значение, правильность контекста и точность источника. Валидатор не оценивает эти четыре свойства целиком.
- В комплекте 21 dev и 90 test PDF, из них 3 и 14 синтетических сканов. Открытый dev-эталон содержит 37 616 строк результатов и 134 замечания. Эталон test не входит в комплект. Эталон dev проверен одним проходом, границы покрытия описаны в `coverage/`.
- **D001/R247.** ThreadRAG / GPT-4o mini / HotpotQA / EM: `.576` → `0.576 fraction`, PDF стр. 6, Table 1. Дословная цитата одной строки содержит много чисел. Для доказательства нужны заголовки колонки и координаты конкретной ячейки.
- **D013/R143.** `24.5 (.29)` на скане — среднее EM и отдельное SD, разные записи. `2` — число запусков, `7405` в R143 — размер выборки из Table 6. Точная ячейка требует визуальной проверки. Простое совпадение `Table 2:` подтверждает только якорь.
- **D002/I01.** Подпись Table II сообщает 156 вопросов General, текст 150. В эталоне у результата оставлено число по подписи, расхождение оформлено замечанием. По такому полю нельзя молча подставить исправление или считать условия совпавшими.
- **D014.** Оцифрованные точки требуют сохранять метод и точность, которые отмечает dev-эталон. Открытый вопрос — где провести границу между приближённой числовой записью и ручной проверкой.
