# Комплект участника ВИНИТИ

Официальные условия для предметной области 2 описаны на страницах 7–11 PDF. Состав сдачи кратко изложен в [описании кейса](../case.md). [Задание ВИНИТИ](ВИНИТИ+ЮФУ.pdf#page=7)

## Где разместить файлы

Возьмите у команды комплект участника от 20 ноября 2026 года и распакуйте его в `docs/context/RAG_ВИНИТИ_участникам_2026-11-20/` от корня репозитория. Проверьте, что `README_участникам.md` и каталоги из таблицы лежат непосредственно внутри. Git игнорирует эту папку.

| Путь внутри комплекта | Для чего нужен |
| --- | --- |
| `README_участникам.md`, `CHECKLIST.txt` | Статус комплекта, перечень PDF и контрольные суммы. В README от 20 ноября комплект отмечен как подготовительный. |
| `dev/` | 21 PDF (`D001`–`D021`). `D002`, `D013` и `D021` — синтетические сканы без текстового слоя. |
| `dev_gold/` | Открытый эталон всех 21 dev-статей. CSV содержат записи, `coverage/` описывает границы разметки, `README_STATUS.md` объясняет статус. |
| `test/` | 90 PDF (`P001`–`P090`), из них 14 синтетических сканов. Эталон test хранится у организаторов. |
| `submission_template/` | Заготовки семи CSV, полное описание полей в `README.md` и точная схема в `schema.json`. |
| `tools/` | Валидатор `check_submission.py` и его зависимости `requirements.txt`. |

Разметка dev сделана по исходным PDF и проверена по источнику одним проходом. В синтетических сканах сохранены порядок страниц и видимые значения. При расхождении со сканом сначала откройте страницу и проверьте OCR. [Контрольные примеры D001 и D013](../research/viniti-pdf-extraction.md#два-контрольных-примера)

## Как устроен рекомендуемый формат

| CSV | Содержание |
| --- | --- |
| `publications` | Библиография и решение о включении. Строка для каждого PDF проверяемого набора. |
| `configurations` | Метод поиска, модели, разбиение текста, retrieval top-k и параметры генерации. Варианты и абляции оформляются отдельно. |
| `datasets` | Набор, версия, разбиение и сведения, указанные в статье. |
| `tasks` | Описанная в статье задача. |
| `experiments` | Протокол оценки, baseline и условия сравнения. |
| `results` | Одна метрика и одно значение с исходной записью, источником и связями с конфигурацией, набором, задачей и экспериментом. |
| `issues` | Замечания со ссылками на результаты и место проверки. |

`publication_id` равен имени PDF без расширения. Ключи остальных сущностей уникальны внутри публикации. По исключённой публикации заполняется только `publications.csv` с причиной. Пустая ячейка обозначает отсутствие сведений. Ноль сохраняется числом. Значение, явно приведённое в статье, хранится с исходной шкалой и записью, а нормализация требует основания. Для результата указываются номер страницы PDF с 1 и дословный фрагмент или точный указатель на рисунок с пояснением. `top_k` показывает, сколько элементов извлекает система, а `metric_k` задаёт отсечку метрики вроде `Recall@10`. `primary` обозначает результат, полученный авторами работы, в том числе воспроизведённый baseline. `cited` обозначает число, перенесённое из другой работы. Повторное упоминание можно связать через `duplicate_of` после проверки, что речь о том же результате.

Это рекомендуемая адаптация для машинного сравнения. При формировании CSV сверяйте поля, их порядок и служебные значения с `submission_template/schema.json` и `submission_template/README.md` из комплекта.

## Как проверить выгрузку

Откройте терминал в корне комплекта. Подставьте путь к каталогу с CSV вместо `/path/to/submission` и выберите `dev` или `test` по целевому набору.

```bash
python -m pip install -r tools/requirements.txt
python tools/check_submission.py /path/to/submission dev --json-report report.json
```

Для страниц без текстового слоя можно добавить `--ocr --ocr-language eng`. Для этого нужен локальный Tesseract с английскими языковыми данными. Код выхода `0` означает, что выполненные проверки прошли, `1` указывает на ошибку, `2` требует разбора предупреждений или проверки источника. Ненайденную цитату на скане или значение с графика сверяйте визуально. Для оценки полноты и правильности привязки числа к конфигурации сравнивайте записи отдельно с `dev_gold`. > Ответ для всех участников на вопрос с брифинга по предметной области 1: граф связей между статьями строить не следует - корпус слишком маленький и с учетом того, что лицензионные требования позволяют выдать только такой набор статей, они оказываются практически несвязанными.
