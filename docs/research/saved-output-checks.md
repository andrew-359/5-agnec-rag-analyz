# Сверка сохранённых выходов D001, D009 и D013

Три контрольных случая для приёмки общего прогона. D001 и D009 сверены по сохранённым JSON и CSV эталона. Для D013 сверены строки эталона и критерии теста, а наблюдения взяты из отчёта пилота. Повторного чтения PDF, OCR и парсинга не было. Для D001 использованы два отдельных выхода, сквозная публикация здесь не проверялась.

## В каком порядке сверять

1. **Источник.** Найти тот же PDF, страницу и таблицу или рисунок. Для таблицы сверить строку и полный путь по шапке. Для графика — панель, серию и координату по оси X. Идентификаторы `result-*` и `cell-*` ниже помогают открыть конкретный сохранённый выход и локальны для него.
2. **Чтение.** Проверить, есть ли по этому адресу значение либо замечание с прочитанным числом. Для таблицы сравнить десятичное значение и шкалу. Для оцифрованной точки привести обе записи к одной шкале и применить допуск. Неоднозначная точка без числа остаётся пропуском значения с объяснением.
3. **Привязка.** Сверить эксперимент, метрику, датасет и обязательные для этого случая условия. Если поле явно открыто, записать, что именно осталось открытым. Если поле заполнено неверно или число ведёт к другой ячейке, отметить ошибку привязки. Для полного совпадения нужны источник, значение и условия.

У одной записи могут быть несколько расхождений. Например, адрес и число верны, а единица и `top_k` отсутствуют. Отдельно отмечаем, если эталон фиксирует условие, которое статья оставляет неоднозначным.

## D009 — число прочитано, генератор открыт

**Контроль.** Стр. 5, Table 1, строка Search-R1, столбец `HotpotQA → EM`, значение `37.9`. Gold `R111 / E1 / C10` указывает шкалу `%`, `top_k=3` и Qwen2.5-7B-Instruct. В §4.1 модель названа для PRO-STEP и большинства бейзлайнов, без однозначного отнесения Search-R1 к этому большинству. [PDF, стр. 5](../context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D009.pdf#page=5) · [Аудит D009](article-audits/D009.md)

**Сохранённый выход.** В локальном `runs/D009-table-cli/run.json` запись `remark-5` ссылается на `cell-9-4` (строка 9, столбец 4 в сохранённой сетке, индексы с нуля). В ней есть `raw_text=37.9`, `field=generator`, `retrieval_top_k=3` и вариант Qwen2.5-7B-Instruct со свидетельством `qwen`. Подтверждённого результата для этой ячейки нет. Во всём контрольном столбце 11 найденных числовых ячеек, из них три выпущены как результаты и восемь попали в замечания по генератору. Дополнительное замечание уровня таблицы в эти восемь не входит. [Описание сохранённого прогона](../../runs/README.md#d009-из-реальной-сетки-docling)

**Решение при сверке.** Для Search-R1 засчитать чтение числа и адреса, а при сверке записей оставить открытое условие генератора. Если будущий прогон подтверждает модель, проверяем его собственное свидетельство применительно к этой строке. Копия модели из gold без такого свидетельства считается ошибкой привязки. Контрольный пример полного пропуска — ни в результатах, ни в замечаниях по указанной ячейке нет числа `37.9`.

## D001 — два значения .422 с разными источниками

Оба относятся к ThreadRAG, HotpotQA, EM и шкале долей. По эталону это два разных эксперимента. Координаты ниже — строка и столбец в сохранённой сетке с нуля. [Аудит D001](article-audits/D001.md#контрольная-сверка)

| Контроль | Эталон и условия | Сохранённый выход |
| --- | --- | --- |
| [Стр. 6, Table 1](../context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D001.pdf#page=6), строка ThreadRAG, `LLaMA3-8B-Instruct → HotpotQA → EM` | `R235 / E1 / C40`, `0.422`, LLaMA3-8B-Instruct, `top_k=5` | [Снимок Table 1](../../runs/snapshots/D001/run.json), `result-234`, `cell-18-1`. Число, модель и адрес совпадают. В снимке `top_k` пуст |
| [Стр. 7, Table 2](../context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D001.pdf#page=7), строка со всеми галочками, `HotpotQA` | `R257 / E2 / C43`, `0.422`, SN, STG и EDP включены, генератор и `top_k` не указаны | Локальный `/tmp/rag-d001-ablation-verified/run.json`, `result-0`, `cell-2-3`. Число, компоненты и адрес совпадают. Генератор и `top_k` пусты |

**Решение при сверке.** На уровне чтения обе ячейки совпали с эталоном. На уровне условий основная оценка имеет пропуск `top_k`. В общем выпуске обе записи должны сохраниться отдельно и открывать разные ячейки. Если они поменялись ссылками или получили общий эксперимент, это ошибка привязки, даже если оба числа совпали. Если после объединения осталась одна строка, у второй нет опубликованной записи. Перенос модели или `top_k` из основной оценки в абляцию также считается ошибкой привязки.

## D013 — точность и пропуск на растровом графике

**Контроль.** Стр. 9, Figure 2(a), серия PPO, метрика EM. Gold относится к `E3 / C26`. Для проверки координаты Y используем допуск `0.001` в долях (0,1 процентного пункта). Серия, панель и шаг должны совпасть. Допуск применяется к числу после этой проверки. [PDF, стр. 9](../context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D013.pdf#page=9) · [Тест графика](../../tests/test_plot_extract.py)

| Шаг | Эталон | Наблюдение из отчёта пилота | Решение при сверке |
| --- | --- | --- | --- |
| 50 | `R368`, `20.000%` = `0.20000` | `19.986%` = `0.19986` | Ошибка по Y `0.00014` укладывается в допуск. Для полного совпадения отдельно нужна ссылка на отметку PPO в панели (a) |
| 175 | `R373`, `31.800%` = `0.31800` | Неоднозначная отметка рядом с другой линией. Сохранено замечание, значения нет | Пропуск значения с объяснением. Если будущий прогон находит точку, проверяем серию, источник и допуск |

**Решение при сверке.** Число из другой панели или серии считается ошибкой привязки даже при точном совпадении Y. Ссылка только на страницу подтверждает наличие рисунка, для проверки точки нужна её область. JSON растрового пилота в локальных артефактах этой сверки не найден, поэтому координаты точки здесь заново не проверены.
