# Десять прогонов на стыках шагов извлечения

22 ноября 2026. План проверки гипотез и результаты первых прогонов. Хотим выяснить, какие наблюдения одного ридера помогают другому шагу подтвердить значение, его адрес или условия эксперимента. Для каждой проверки ниже задан контроль, при котором связь должна остаться открытой либо измениться предсказуемо.

Основные входы — сохранённые сетки, токены, фрагменты текста, точки графиков и модельные ответы. Granite Vision и PaddleOCR-VL уже вызывались напрямую через Python, в реестр графиков они пока не входят. Для повторов сначала используем сохранённые ответы. Если нужно новое чтение модели, запускаем один GPU-вызов за раз. ## Как сравниваем

1. Фиксируем версию кода, SHA-256 PDF, страницу, область и артефакты. При проверке ридеров даём им одну и ту же область. При проверке привязки повторно используем один выход чтения.
2. Снимаем штатный результат, результат комбинации и контроль с удалённым или подменённым основанием. Меняем ровно один сигнал между сравниваемыми вариантами.
3. После сохранения выходов сверяем с PDF и разметкой. Считаем новые подтверждённые записи с источниками, ложные привязки, потери прежних записей и открытые условия, которые остались видимы. Числа, прочитанные без проверяемой привязки, учитываем отдельно.
4. Фиксируем, какой шаг когда смог использовать сигнал. Правило для `auto` рассматриваем после повторения на другом источнике с сопоставимым дефектом.

В первом цикле P056 проверяет передачу точного числа, D019 — переход от сохранённого наблюдения к условию из текста, D015 — перенос того же подхода на сложную шапку. Общий вопрос к границе пайплайна — какие уже подтверждённые поля, адреса и открытые условия нужно сохранить, чтобы повторно привязать измерение по дополнительному источнику.
