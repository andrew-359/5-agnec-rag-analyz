# Компоненты для показателей в паспорте данных

22 ноября 2026 года.

Для компактного паспорта подходят горизонтальные полосы на CSS с видимыми названиями и числами. Долю с известным верхним пределом можно показать нативным `<meter>`, а выполнение запланированных этапов — `Progress` из уже установленного `radix-ui`. Если появится диаграмма с общей числовой осью, несколькими рядами или клавиатурным обходом подсказок, подойдёт Recharts 3. Веб-клиент использует React, `radix-ui` и собственные стили паспорта. ## Готовые компоненты

| Вариант | Возможности и условия подключения |
| --- | --- |
| Radix Primitives `Progress` | Импорт из `radix-ui`, части `Progress.Root` и `Progress.Indicator`. `value` и `max` задают прогресс задачи, `getValueLabel` позволяет озвучить «6 из 8 этапов». Привязать доступное имя к видимой подписи через `aria-labelledby`. Заполнение и вид полосы задаются CSS. [Документация Radix](https://www.radix-ui.com/primitives/docs/components/progress) · [Роль `progressbar`](https://www.w3.org/TR/wai-aria-1.2/#progressbar) |
| HTML `<meter>` | Встроенный индикатор значения в известном диапазоне. Подходит для доли охвата зафиксированного выпуска при положительном знаменателе и согласованных единицах числителя и знаменателя. Рядом остаётся читаемое «3 из 5 рисунков». [HTML Standard](https://html.spec.whatwg.org/multipage/form-elements.html#the-meter-element) · [W3C Meter Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/meter/) |
| Recharts 3 `BarChart` | Горизонтальные полосы строятся с `layout="vertical"`, числовой `XAxis` и категориальной `YAxis`. `LabelList` выводит значения, `ResponsiveContainer` измеряет родительский блок, которому нужно задать высоту. `accessibilityLayer` включён по умолчанию в 3.x. Стандартный `Tooltip` озвучивает данные при переходе между точками стрелками. [API `BarChart`](https://recharts.github.io/en-US/api/BarChart/) · [API `LabelList`](https://recharts.github.io/en-US/api/LabelList/) · [API `ResponsiveContainer`](https://recharts.github.io/en-US/api/ResponsiveContainer/) · [Доступность Recharts](https://github.com/recharts/recharts/blob/main/storybook/stories/API/Accessibility.mdx) |
| shadcn/ui `Chart` | Копируемый `ChartContainer` поверх Recharts, конфигурация подписей и цветов через CSS-переменные, готовое оформление подсказки и легенды. В каталоге есть горизонтальный пример для подбора компоновки. Обёртка подходит, если несколько графиков должны переиспользовать одно оформление. [Документация Chart для Radix](https://ui.shadcn.com/docs/components/radix/chart) · [Горизонтальный пример](https://ui.shadcn.com/view/new-york-v4/chart-bar-horizontal) |
| Nivo `ResponsiveBar` | `@nivo/bar` поддерживает SVG-полосы, `layout="horizontal"`, сгруппированные и составные серии, подсказки и настраиваемый рендер полосы. Для SVG есть `isFocusable` и `barAriaLabel`. Адаптивному компоненту нужна заданная высота родителя. [Документация Bar](https://nivo.rocks/bar/) · [Типы Nivo](https://github.com/plouc/nivo/blob/master/packages/bar/src/types.ts) · [FAQ](https://nivo.rocks/faq/) |
## Что выводить в паспорте RAG

Добавить в конец тела существующего диалога «Паспорт данных», перед строкой скачивания, секцию «Охват и проверка». Она открывается вместе с паспортом. Стиль — белый фон, один синий акцент, серый для остатка, янтарный для предупреждений. Числа и единицы видны рядом с полосами. Длинные причины доступны в раскрытии. Ссылка «Проверки» ведёт к замечаниям того же выпуска, когда этот переход поддерживается текущим экраном. Кнопка «Скачать ZIP» остаётся основной. ### Данные первого среза

| Показатель | Расчёт | Что пояснить в интерфейсе |
| --- | --- | --- |
| Прочитано таблиц из плана | `coverage.readTables / coverage.plannedStages` | Табличная сетка прочитана. Связывание значений с условиями и публикация происходят отдельно. В деталях показать число обнаруженных кандидатов и объектов вне плана, если соответствующие поля доступны. |
| Откуда пришли опубликованные результаты | Один результат из `data.results` относится к одному типу по своему первому `evidenceId`. Явная таблица или рисунок имеют приоритет над запасной классификацией по точности. Без определённого типа — «Другое». | Три горизонтальные полосы с числами: таблицы, рисунки, текст. Другие источники добавляют четвёртую строку при наличии. Подсчёт идёт по строкам выпуска после сверки. |
| Проверка выгрузки | `report.json` закреплённой версии. Число элементов `errors` и `warnings`, при необходимости `quotes.matched / quotes.requested` | Предупреждения чекера и замечания извлечения показывать отдельно. Если чекер использует только текстовый слой, для сканов указывать это ограничение. |
| Графики с опубликованными результатами | Вторым этапом показать число уникальных рисунков с основным источником в опубликованных строках из числа объектов фигур, когда сопоставление по странице и обозначению возможно. | Обработанный рисунок может быть иллюстрацией и дать ноль результатов. Счётчик «этап завершён» сам по себе ничего не говорит о числе извлечённых графиков. |

Поля `readTables` и `plannedStages` формируются на сервере из этапов прогона. Для старых, импортированных и региональных выпусков структура охвата может содержать только статус и текст или координаты области. Пропущенные значения не превращаются в нули. При нулевом знаменателе показываем «Таблицы не входили в план». Для регионального выпуска показываем страницу области и состав его результатов. Загружаем отчёт независимо от паспорта, по тому же адресу версии. Ошибка этой загрузки не блокирует просмотр паспорта и ZIP. ### Пример на сохранённом D001

Локальный выпуск `408d65f` содержит 300 результатов и 63 замечания. Из 10 обнаруженных табличных кандидатов 7 вошли в план, 6 прочитаны, 2 таблицы представлены в опубликованных строках. По основному источнику 279 результатов пришли из таблиц, 19 из рисунков, 2 из текста. Чекер сообщил 0 ошибок и 4 предупреждения, в текстовом слое нашлись 359 из 363 запрошенных цитат.

```text
Охват и проверка

Таблицы прочитаны     █████████████████░░░    6 / 7 · 86%
В выпуск вошли данные из 2 таблиц

Источники 300 результатов
Таблицы    ████████████████████  279
Рисунки    █                      19
Текст      ▏                       2

Чекер выгрузки   0 ошибок · 4 предупреждения
```

«86% прочитанных таблиц в плане» можно показать на любом выпуске с такими счётчиками. «Процент найденных чисел» рассчитывается на отдельной проверке с эталоном, закреплённым за версией. Например, 288 из 415 совпадений по D001 относятся к прежнему выпуску, и это значение нельзя переносить на `408d65f`. На P056 3 из 3 сеток были прочитаны, а ручная сверка Table II дала 57 из 155 чисел. В отчёте P056 чекер искал цитаты только в текстовом слое. [Сверка D001](../../.scratch/viniti-functional-acceptance/spec.md) · [Аудит P056](p056-table-ii-coverage-2026-11-21.md)

### Реализация одним срезом

1. Выделить расчёт показателей для закреплённого выпуска на основе структурированных полей. Использовать основную ссылку результата, чтобы не считать отдельно страницу описания условий.
2. Встроить компактный блок в общий паспорт React. Для зафиксированной доли использовать готовый HTML `<meter>` и CSS, для разбивки — горизонтальные полосы с текстовыми значениями. Radix Progress подходит для такого же визуального языка в незавершённом прогоне. Если понадобится интерактивное сравнение прогонов, отдельно добавить Recharts по открытому примеру горизонтальных столбцов.
3. Проверить выпуск D001, скан P056, выпуск по области и старую версию без детального охвата. Убедиться, что счётчики отчёта меняются вместе с выбранной версией, а скачивание остаётся доступно при отсутствии отчёта.
