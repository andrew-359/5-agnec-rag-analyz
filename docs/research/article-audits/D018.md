## Контрольная сверка

- **Table 3, с. 8.** Пять блоков × девять моделей × пять столбцов дают 225 ячеек, из них 216 числовых и девять `absent`. В блоке (a) Overall ячейка `GPT-4o / Overall (561)` содержит `76.8` % (`R057`), а соседняя `Wikipedia (165)` — `87.3` % (`R058`). Скобки задают число QA. Для точности ответов берут большинство из трёх бинарных оценок одного и того же судьи. - **Table 3(d), с. 8.** В строке GPT-4o под `Product Review (0)` напечатано тире (`R195`, `absent`), под `Company Rules (2)` — `0.0` % (`R196`, измеренное значение). В Product Review нет вопросов Computing, поэтому тире стоит во всех девяти строках моделей. ## Что дал прогон

В сохранённом CLI-прогоне Docling + TableFormer нашёл Table 3 и подпись. В сетке 62×6 совпали 192 из 216 чисел по строгому разбору ячеек и 212 из 216 при поиске числовых токенов. CSV содержит только заголовок. Код завершения 0, сохранено 210 замечаний о неоднозначной привязке числа к условиям. Девять ожидаемых тире учтены отдельно от 216 числовых значений. [Попытка](../../../runs/benchmark-2026-11-21.hSazlU/attempts.json) · [Оценка](../../../runs/benchmark-2026-11-21.hSazlU/scores.json) · [CSV CLI](../../../runs/benchmark-2026-11-21.hSazlU/D018-p8-t3-docling-tableformer/results.csv)

Пять блоков попали в одну сетку. Например, CLI записал `81.7 25.2` в `cell-16-1` и перенёс в её путь заголовки блока Overall. В PDF это две соседние строки GPT-4o и llm-jp-1.8B в блоке Extracting. Даже отдельное число `76.8` в `cell-2-1` осталось замечанием с пустыми условиями, хотя его шапка прочитана. В `run.json` отсутствуют ссылки на контекст §4.1 со с. 7, где описан Naive RAG. Для привязки записи нужны тип вопроса из блока, генератор из строки, корпус и размер выборки из столбца, метрика из подписи и условия из протокола.
