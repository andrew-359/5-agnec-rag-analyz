Дальше приведены страницы PDF с единицы и индексы строк и колонок сетки с нуля. Проверка относится к этим трём таблицам.

Фактический импорт — [`rag_mvp/__init__.py`](/home/andrew/dev/RAG-worktrees/rag-empty-table-audit/rag_mvp/__init__.py). Чтение для CLI выполнено из сохранённых JSON, PDF использован для сверки. Выходы и диагностические пробы лежат в [/tmp](/tmp/rag-empty-table-audit.AhvjnQ). Код проекта и входные артефакты сохранены.


## Кандидат на следующий фикс

Один адаптер для QA-таблиц, где подпись прямо задаёт Accuracy для всей таблицы, а вложенная шапка задаёт датасет и условие измерения. Выдавать утверждения о метрике из подписи и о каждом условии из его источника, затем передавать их в общий `assemble()`. Подтверждение задачи и области эксперимента должно пройти для обеих таблиц. Простой допуск второго заголовка в список метрик эти роли смешает.

Два контрольных примера на штатном CLI с теми же сетками и текстом:

- **P012 Table 2, `cell-3-1`.** Получить `58.12`, Accuracy с единицей `%`, NQ, генератор L3.1-8B и вариант источников RP. Для Accuracy и единицы открыть подпись, для датасета и генератора открыть разные уровни шапки, для RP открыть строку и описание пула. После удаления свидетельства Accuracy оставить число и рамку с открытой метрикой.
- **P062 Table 7, `cell-2-1`.** Получить `39.40`, Accuracy, Non-RAG, BLEnD, культурный срез `am` и генератор Llama-3.2-1B. Для Accuracy и модели открыть подпись, для датасета и среза открыть оба уровня шапки, для метода открыть строку. Единицу хранить при явном подтверждении. Смена подписи на подпись соседней Table 8 должна блокировать привязку генератора к Table 7.
