# Пять статей из test — карты и ручной эталон

Контрольная выборка для будущего прогона. В ней 51 основное числовое значение, три явно пустых результата и отдельные проверки для дельт и значений после `±`. Это ручная разметка выбранных фрагментов, с одним проходом сверки по PDF. Официальный test gold хранится у организаторов. За образец взяты [карточки dev](README.md) и [описание dev gold](../../context/RAG_ВИНИТИ_участникам_2026-11-20/dev_gold/README_STATUS.md).

## Как выбраны статьи

Из 90 PDF сначала выделены пять групп по наличию текстового слоя, длине и числу меток таблиц и рисунков. В каждой группе имена отсортированы по `P###`. Из каждой взят один файл через `random.Random(21112026).choice`, в порядке строк таблицы. Метки считались по строкам извлечённого текста как приближение для отбора. Например, нумерация приложений вида `Table S1` в этот подсчёт не входит. Контрольные источники внутри статей выбраны вручную.

| Группа | Правило отбора | Статья | Что проверяем |
| --- | --- | --- | --- |
| Скан | Ни на одной странице нет текстового слоя | [P033](#p033--scan) | OCR, вложенные группы метрик, два протокола поиска |
| Короткая цифровая | До 10 страниц включительно, от двух меток таблиц | [P079](#p079--multi-field-hybrid-retrieval) | Две таблицы в одной колонке, римские номера, разный top-k |
| Много таблиц | От 15 меток таблиц, до девяти меток рисунков включительно | [P057](#p057--from-rag-to-riches) | Группы строк, пропуски, разные настройки поиска |
| Много рисунков | От 13 меток рисунков, меньше 12 меток таблиц | [P066](#p066--astrid) | Величины после ±, роли моделей, точные числа из легенды |
| Длинная цифровая | От 21 страницы, до восьми меток таблиц включительно, меньше 13 меток рисунков | [P017](#p017--real-mm-rag) | Основной балл и прирост в одной ячейке, срезы датасета, cutoff метрики |

Все номера страниц ниже считаются от 1 в порядке PDF. Адрес табличного результата задают PDF, страница, таблица, строка и полный путь по шапке. Строка эталона с несколькими числовыми столбцами задаёт по одному результату на столбец. Числа записаны в масштабе источника и с его точностью. Для составной ячейки основной балл и дополнительное число проверяются раздельно по той же ячейке.

## P079 — Multi-Field Hybrid Retrieval

*Multi-Field Hybrid Retrieval-Augmented Generation for Maritime Accident Root Cause Analysis*, Seongjin Kim и Sungil Kim. 6 страниц, компактный двухколоночный цифровой PDF. Задача — найти похожие решения по морским происшествиям и построить описание причин и набор тегов.

## P057 — From RAG to RICHES

*From RAG to RICHES: Retrieval Interlaced with Sequence Generation*, Palak Jain, Livio Baldini Soares и Tom Kwiatkowski. 18 страниц, цифровой PDF. Статья сравнивает базовые конфигурации open-domain QA с поиском, встроенным в генерацию.

| Страницы PDF | Что на них |
| --- | --- |
| [1–5][p057-1] | Постановка, метод, beam search, индексируемые единицы и определения метрик |
| [6–7][p057-7] | Примеры single-hop и multi-hop QA, сравнение retrieval keys в Table 3 |
| [8–9][p057-8] | Итоговое сравнение в Table 4, абляции в Tables 5–6, отдельный анализ поиска в Table 7 на стр. 9 |
| 10–11 | Список литературы |
| [12–18][p057-12] | Приложение с промптами, дополнительными результатами и примерами ошибок |

В Table 4 под каждым датасетом повторяются `F1` и `AutoAIS`. F1 измеряет совпадение ответа, AutoAIS — подтверждение вопроса и ответа извлечённым свидетельством. `PaLM2-M` — модель из столбца `Answerer`. Для `GTR Passage` подпись задаёт `k=1`, для `GTR Proposition` — `k=2`, для `Iterative` — по одному документу за шаг и до четырёх документов. Эти значения не переносим на группу `RICHES`. | [стр. 8, Table 4][p057-8] | No Retrieval → Unconstrained → PaLM2-M | 41.4 | — | 39.1 | — | 18.3 | — |

| Источник | Группа и конфигурация | NQ → F1 | NQ → AutoAIS |

Числа `40.2` и `59.2` также встречаются в Table 5 при `Beam=10`. Размер beam относится к декодированию, а для контрольных результатов нужен адрес в Table 4. [Tables 4–5][p057-8]

## P066 — ASTRID

*ASTRID - An Automated and Scalable TRIaD for the Evaluation of RAG-based Clinical Question Answering Systems*. 17 страниц, цифровой PDF. Статья предлагает проверять ответы клинической QA-системы по CF, CR и RA и оценивает согласие таких проверок с человеческой разметкой.

Для каждого PDF отдельно считаем, сколько контрольных источников найдено, сколько основных чисел прочитано и сколько результатов совпало по значению, метрике, условиям и адресу. Ячейки сверяются по полной шапке и строке. Для составных ячеек проверяется, что ссылка ведёт в ту же ячейку, а при наличии отдельной подсветки каждого числа — в нужную часть. Дополнительные числа и пропуски проверяются отдельно. Карты страниц подсказывают, где искать остальной материал; по этой выборке можно измерить совпадение на контрольных фрагментах.
