## Appendix G. Количество ошибок HotpotQA

Штатная точка входа `rag_mvp.prose_results` получила сохранённый `article-text.json` схемы 1 с `--failure-counts`. Выборка извлечена из текста до сверки с `dev_gold`. Среда прогона использовала Python 3.12.3 и pdfplumber 0.11.10. Для независимой сверки координат и текста использован Poppler 24.02.0. [Команда, версии и SHA-256 текста](../../runs/D001-appendix-g/attempt.json) · [Выход обработки](../../runs/D001-appendix-g/prose-results.json).

```bash
python -m rag_mvp.prose_results "$corpus/dev/D001.pdf" \
  --article-text "$article_text" --failure-counts --out "$out/prose-results.json"
```

В команде `corpus` указывает на каталог комплекта участника, `article_text` на сохранённый фрагментированный текст с SHA-256 `db4d715651eaa2699c0c138acbe86b012807f429eca8db2185c5238f5026cd0d`, `out` на новый каталог прогона. Путь к исходному артефакту текста записан в `attempt.json`.

| Категория | Извлечено случаев | Эталон | Адрес цитаты на PDF 16 |
| --- | ---: | --- | --- |
| Retrieval Failure | 149 | R399 | `7fcbb21b0bdf-p16-text-11-quote-312-348`, первая рамка под Figure 6 |
| LLM Analysis Error | 42 | R403 | `7fcbb21b0bdf-p16-text-12-quote-326-362`, нижняя часть левой колонки |
| Pathfinding Error | 9 | R407 | `7fcbb21b0bdf-p16-text-13-quote-410-443`, верхняя часть правой колонки |

В каждой записи есть отдельная цитата знаменателя `7fcbb21b0bdf-p16-text-11-quote-13-116`. Она включает HotpotQA и фразу `we randomly sampled 200 incorrect prediction cases`. У знаменателя и `Retrieval Failure` разные диапазоны текста в одном фрагменте. Координаты даны с точностью до рамки фрагмента, текст цитаты сохранён с точным диапазоном. Счёт 3/3 охватывает категории, целые количества и общий знаменатель. Проценты и повторы в Figure 6 исключены из счёта. [Исходная страница PDF](../../docs/context/RAG_ВИНИТИ_участникам_2026-11-20/dev/D001.pdf#page=16) · [Превью с рамками](../../runs/D001-appendix-g/page-16-bounds.png) · [Сверка с эталоном](../../runs/D001-appendix-g/attempt.json).

Контроль без `--failure-counts` дал побайтово одинаковый выход до и после правки. В сохранённом входе пилота без табличных данных есть пять замечаний обработки приростов EM. Для показа Appendix G на D001 достаточно выводить три количества и обе ссылки на источники. Перед применением правила в других статьях нужна проверка области действия знаменателя при другой вёрстке и формулировке. [Контроль до](../../runs/D001-appendix-g/baseline-before.json) · [Контроль после](../../runs/D001-appendix-g/baseline-after.json).

### Точное чтение подписей векторных столбцов

`vector-bar` читает подписи через PDFium и связывает их со столбцами по положению, с серией по цвету легенды, с группой по положению на категориальной оси. Публикуем число как напечатано, с рамкой подписи; высота или длина столбца не участвует в расчёте. Один неподтверждённый столбец остаётся замечанием, подтверждённые сохраняются. Модель и новые зависимости не понадобились.

```bash
python -m rag_mvp.plot_extract "$corpus/dev/D001.pdf" --page 8 --figure 5 --panel 1 \
  --series '' --x-axis X --y-axis Y --strategy vector-bar --out "$out/d001-figure5.json"
```

На D001 совпали все 12 связок из ручного контроля. На D006, PDF-страница 15, Figure 5, тот же CLI совпал с `dev_gold` по всем 24 числам с серией и группой: 12/12 для BM25 и 12/12 для Contriever, без лишних результатов. Полный прогон и публикация проверены на D001; D006 проверялся лишь через CLI, так как автоматическая публикация ограничена одной панелью со шкалой Exact Match в долях.

## Figure 2. Поиск надписи внутри схемы

`python -m rag_mvp inspect` сохраняет карту с подписью Figure 2. `search-figure-labels.py` берёт эту подпись и заданную область `[71, 57, 526, 286]` на PDF-странице 3 и запускает оба варианта для одного запроса `Graph Pruning`. Фраза сопоставляется без учёта регистра. Для чтения внутри области учитываются символы, целиком лежащие в её границах. Попадания из основного текста статьи в этот прогон не входят. Среда использовала Python 3.12.3, pdfplumber 0.11.10, pdfminer.six 20260107, pypdfium2 5.15.2 и Pillow 13.0.0. Параметры текстового слоя `x_tolerance=3`, `y_tolerance=3`, `layout=false`, разрешение превью 144 dpi. [Команды воспроизведения](../../runs/README.md#d001-поиск-надписи-в-figure-2).

| Вход поиска | Совпадений | Сохранённый выход |
| --- | ---: | --- |
| Подпись из карты статьи | 0 | [caption.json](../../runs/D001-figure2-label-search/comparison/caption.json) |
| Та же подпись и текст внутри области | 1 | [caption-and-labels.json](../../runs/D001-figure2-label-search/comparison/caption-and-labels.json) |

Карта содержит первую строку многострочной подписи. Остальные строки вручную проверены по PDF, фразы там нет. Результат второго режима ведёт к `Graph Pruning` в блоке Energy-Driven Pathfinding. Рамка надписи `[434.308, 185.406, 479.377, 192.976]` указана в пунктах от верхнего левого угла и сверена визуально. При независимом чтении Poppler рамка `[434.308, 184.596, 479.377, 192.976]` начинается на 0.81 пункта выше. Остальные стороны совпадают после округления. [PDF-страница 3](../../runs/D001-figure2-label-search/article-map/source.pdf#page=3) · [Схема с рамкой](../../runs/D001-figure2-label-search/comparison/figure.png) · [Координаты Poppler](../../runs/D001-figure2-label-search/page-3-poppler.xhtml).

Локальный результат позволяет показать переход на D001 от запроса к надписи. Для поиска по другим рисункам сначала стоит проверить, охватывают ли автоматически найденные границы надписи схемы и отсекают ли соседний текст. Растровые схемы потребуют отдельной проверки OCR.
