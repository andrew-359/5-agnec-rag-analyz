# Проверка правок извлечения на dev_gold

Для правки, которая меняет извлечение, привязку или публикацию табличных результатов, сравниваем базу и кандидат на одних входах D001–D021. Локальные проверки отдельной статьи помогают найти причину ошибки. Решение о переносе принимаем после замера на всех 21 статьях и отдельного контроля P020. Для замера используем текущий рабочий каталог и сохранённый baseline.

## Что фиксировать один раз

Сохранить завершённые Auto-артефакты всех 21 dev-статей в каталоге со структурой `Dnnn/01`. Для каждой нужны паспорт прогона `run.json`, сохранённый общий текст, сетки и итог сверки. Явно записать неудачные попытки. Добавить завершённый контроль P020 со стр. 5, Table 1 в том же формате. В нём сохранена непустая сетка описательной статистики. Использовать сохранённые сетки и текст повторно при правках привязки. Для смены самого ридера зафиксировать тот же список PDF и заново собрать входы у обеих версий, сохранив результаты отдельных попыток.

Текущий остановленный dev-прогон даёт один завершённый вход D001. Пока нет полного снимка, метрики по всем 21 не публикуем.

## Прогон правки привязки

```bash
# Перед правкой в текущем checkout
python scripts/eval_batch.py "$DEV_REPLAY_INPUT" --predictions "$OUT/baseline.json"
# После правки на тех же файлах
python scripts/eval_batch.py "$DEV_REPLAY_INPUT" --predictions "$OUT/updated.json"
python scripts/score-dev.py "$OUT/baseline.json" "$DEV_GOLD" "$OUT/quality.json" \
  --updated "$OUT/updated.json"
```

`DEV_REPLAY_INPUT` указывает на замороженный набор D001–D021 и P020. `OUT` — отдельный каталог сравнения. Записываем SHA кода базы и кандидата рядом с результатом. В режиме повтора `score-dev.py` требует совпадения SHA PDF, общего текста и сеток. Для сравнения политик публикации подаём парный JSON с `article`, `baseline`, `updated` и массивами строк публикации обеих политик. В строке P020 также нужен `read_tables: [[5, 1]]` из успешного повтора контроля. При смене ридера парный JSON формируем по одинаковым PDF и отдельно записываем отличия чтения и охвата.

## Как принять результат

- `score-dev.py` отклоняет набор с пропусками или дублями dev-статей. Для каждой политики считает точность и полноту по извлечённым табличным строкам `dev_gold` в целом и по статьям. Сопоставление один к одному по странице, таблице, метрике, отсечке и исходному числу. Отдельно считает более строгий ключ с методом, датасетом и генератором. Эти показатели не проверяют рамку ячейки или совпадение протокола.
- P020 Table 1 должен быть прочитан в обеих версиях. Если хотя бы одна версия выпустила измерение из этого контроля, скрипт сохраняет число ложных строк и завершает проверку кодом 1.
- В отчёте показать дельты обеих пар Precision/Recall и назвать регрессии по статьям. Ручную сверку делать по обнаруженным расхождениям, используя PDF для объяснения.
