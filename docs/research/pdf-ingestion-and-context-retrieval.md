## Ридеры и структура

Текущий штатный текстовый путь группирует слова `pdfplumber` в строки и абзацы, ищет просвет между колонками внутри страницы и выдаёт по одному `Evidence` с исходным ID, текстом и рамкой на фрагмент. Цифровой разбор идёт постранично. OCR-стратегия запускает Docling с RapidOCR на пустых страницах по одной и отбирает текст/заголовки/подписи с единственным `prov`. Метки блоков при этом в общем артефакте не сохраняются. Табличная подборка уже использует регулярные выражения для заголовков и авторских ссылок, но продолжение между колонками в `condition_blocks` ограничено одной страницей. Подборка для фигур рассчитана на частный сценарий sensitivity / Exact Match. ## Подборка без замены ридера

1. Для одной версии PDF брать цель и открытое поле. Цель включает таблицу или рисунок с панелью, подпись, имя метода/серии и известные метрики/условия из сетки или наблюдения. Собрать кандидатов по точным ссылкам на цель, номеру и типу раздела, затем по словам запроса во всём тексте этой статьи. Номер панели и одноимённые цели приложения проверять вместе с подписью и страницей. Подпись, упоминание в прозе и число из клетки играют разные роли. [Контракт контекста](../../.scratch/article-context-and-reconciliation/spec.md)
2. Для кандидата оставить исходные блоки и при необходимости собрать поисковое окно из соседнего текста того же раздела. На границе страниц искать последнее и первое продолжения основного текста, пропуская распознанные подписи и колонтитулы. Учитывать колонку, пунктуацию и разрыв слова. Неопределённое продолжение остаётся парой кандидатов для проверки. Для D011 `ca- / pacity` индексируем слитно, а цитата и рамка для каждой страницы берутся по двум прежним ID. Заголовок, авторский номер, тип, порядок и причина соседства могут храниться отдельно от исходного `Evidence`. При другом ридере сохранять его исходный `self_ref`, XML ID или `block_id` в пространстве конкретного артефакта и версии, отдельно от проектного ID. Сопоставлять с прежними фрагментами по странице, области и тексту, сохраняя обе ссылки. Перенумерация блоков другого ридера не меняет адресов прежних прогонов. [Формат Evidence](../../rag_mvp/article_context/reader.py) · [Требования к источникам](../../.scratch/source-links/spec.md)
3. Передать список ID в привязку конкретной строки или наблюдения. Проверить цель, группу, метрику, ось и область действия каждого условия. В D019 полю датасета нужен собственный адрес, у значения остаётся адрес точки. При отсутствии применимого основания оставить поле открытым и сохранить уже прочитанное наблюдение с рамкой. [Повтор D019](../../../RAG-worktrees/rag-d019-figure-context/runs/d019-figure-context-replay/README.md#где-обрывается-привязка)

**Поиск.** SQLite FTS5 в памяти даёт фразы, префиксы и BM25. В read-only пробе на сохранённых JSON (SQLite 3.45.1, один фрагмент на строку, `unicode61`, убраны поисковые переносы слов, первые пять по BM25) запрос `"Table 10" AND WRR` не дал совпадений из-за `WRRs`, а `"Table 10" AND (WRR OR WRRs) AND KMW` вернул нужный абзац D011 первым. `"Figure 5" AND WRR` и `"100 queries" AND WRR` по отдельности вернули две половины продолжения. На D019 `"figure 3" AND recall` вернул нужный §3.6 вторым, выше стоит текст с PDF 8. Это проверка достижимости заранее известных мест. Для теста поиска запросы формируются только из сохранённой цели и открытого поля. Например, до поиска D019 имя Huatuo-26M неизвестно. [FTS5](https://sqlite.org/fts5.html#auxiliary_functions) · [Лицензия SQLite](https://sqlite.org/copyright.html) · [Вход D011](../../runs/D011-auto.Qvb8rzkT/cli/01/article-text.json) · [Вход D019](../../runs/gold-holdout/d019/article-text.json/article-text.json)

**Семантический вариант.** После лексического baseline можно проверить BGE-small-en-v1.5 (MIT, английский, 384 измерения, до 512 токенов) на тех же текстах, окнах, ID и запросах. Локальный энкодер работает на CPU или CUDA, затем достаточно точного косинуса в памяти. Для гибрида сохранить точные ссылки как приоритет и объединить остальные лексический и семантический списки по рангам. У сравниваемых вариантов одинаковые фильтр SHA статьи, правила расширения соседями, лимит кандидатов и проверка применимости. Гипотеза выигрыша — перефразированный запрос без общего словаря. Аббревиатуры, числа и номера объектов остаются точными ограничениями. На нескольких сотнях блоков достаточно полного перебора векторов, поэтому векторный сервер в этот пилот не входит. Для PP-StructureV3 мерой выигрыша будет хотя бы одна раньше ошибочная цитата с верной рамкой (например, вся подпись Figure 2 на PDF 9) без потери подтверждённых цитат PDF 6. Запасной тест GROBID имеет смысл, если на цифровом тексте остаются пропущенные или неверно связанные ссылки Figure/Table. - **Критерий решения.** Раздельно считать долю доступных исходных цитат с верной рамкой, `recall@5` по размеченным основаниям (для D011/Figure 5 должны попасть обе части), подтверждённые поля по выбранным строкам и ложные привязки. Фиксировать PDF SHA, артефакты и версии, OCR/DPI, затраты CPU/памяти. Оставить текущий ридер на цифровом пути, если альтернативный не восстанавливает отсутствующий адресуемый фрагмент либо не улучшает порядок с верным происхождением. При росте recall без новых проверяемых связей сохраняется задача на стыке с предметной привязкой. Семантику принимать только при выигранном контрольном запросе на том же корпусе без потери точных запросов и при нуле ложных подтверждений.
