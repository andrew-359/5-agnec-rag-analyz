# pdfplumber: цифровые таблицы и карта статьи

Для карты статьи используем `pdfplumber==0.11.9`. Он читает текст и геометрию PDF без запуска нейросети. Для таблиц это кандидат на алгоритмический разбор: пригодность ещё нужно проверить на наших разных видах шапок. Текущий `extract` продолжает использовать Docling.

## Что берём готовым

У библиотеки есть координаты слов и символов, линии, прямоугольники и изображения. Для таблиц доступны `find_tables()` с геометрией, `extract_tables()` с текстом и `debug_tablefinder()` для проверки сетки. Стратегия `lines` опирается на линии и границы прямоугольников, `lines_strict` исключает границы прямоугольников, `text` использует выравнивание слов, `explicit` — заданные границы. Лучше всего библиотека работает с цифровыми PDF; OCR в неё не входит. [Документация pdfplumber](https://github.com/jsvine/pdfplumber#extracting-tables).

## Как встроить в наш проект

Путь: карта статьи → выбор таблицы → определение её области → восстановление сетки → адаптер `ReadTable`/`ReadCell` → существующие правила результатов метрик.

Сейчас реализован первый шаг. Подпись помогает найти страницу, но её прямоугольник нельзя передавать как область всей таблицы: тогда останется только подпись. Связь подписи с таблицей определяем отдельно, особенно когда на странице несколько таблиц.

Для следующего шага сравним два режима на одинаковых областях:

| Вид таблицы | Первая проба | Что проверяем |
| --- | --- | --- |
| Есть полноценная сетка | `lines` | Не потеряны ли строки и объединения |
| Только несколько горизонтальных черт | `lines` и `text` | Не исчезли ли колонки без вертикальных границ |
| Нет линий, есть выровненные колонки | `text` | Не приняты ли абзацы за таблицу |
| Сетка известна из геометрии | `explicit` | Не разрезаны ли числа и многострочная шапка |
| Скан | Отмечаем необходимость OCR | Без отдельного распознавания текста этот путь не подходит |

Пример исследовательского вызова, ещё не встроенного в `extract`:

```python
import pdfplumber

with pdfplumber.open("article.pdf") as pdf:
    page = pdf.pages[5]  # Шестая страница PDF.
    settings = {"vertical_strategy": "text", "horizontal_strategy": "text"}
    for table in page.find_tables(settings):
        print(table.bbox, table.extract())
```

Это выдаёт сырую сетку. Назначение колонки — датасет, метод, метрика или условие — всё ещё определяют наши правила. Пустую позицию нельзя автоматически считать нулём или продолжением соседней ячейки. Объединённая шапка требует восстановления связей между уровнями.

## Какие данные сохранять

Наш адаптер должен сохранить исходный текст каждой ячейки, её строку, колонку, область, объединения и путь шапки. Для воспроизводимости сохраняем версию библиотеки, стратегии, допуски и исходный PDF с хешем. Сырые данные отделяем от интерпретации в результат метрики.

Координаты pdfplumber для таблиц имеют порядок `(x0, top, x1, bottom)` в единицах страницы от верхнего края. Для нашего просмотра переводим их в доли ширины и высоты страницы, сохраняя номер страницы PDF с единицы. Не смешиваем их с PDF-координатами от нижнего края. [Описание координат и обрезки](https://github.com/jsvine/pdfplumber#the-pdfplumberpage-class).

## Как решим, подходит ли нам

Сначала D001/Table 1, затем таблица с другой шапкой и отложенная цифровая статья. Сверяем число, правильность привязки к условиям и область источника; отдельно записываем пропуски и ложные ячейки. Сравниваем с существующим Docling на том же входе. Скан D013 служит проверкой ограничения: пустой текстовый разбор не означает отсутствие таблиц.

Обещать стопроцентную поддержку любых статей до таких прогонов нельзя. Если pdfplumber подходит только части таблиц, оставляем его отдельной веткой с явным статусом неподдержанного случая. Новые модели и OCR согласовываем отдельно. Уже существующий Docling использует модели, поэтому весь текущий проект алгоритмическим не называем.
