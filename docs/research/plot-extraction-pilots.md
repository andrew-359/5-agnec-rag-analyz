# Графики из PDF. Проверка инструментов и двух векторных стратегий

Подпись на карте статьи помогает найти рисунок. Для перехода к числу нужны сама панель, деления осей и положение конкретной отметки. В обоих исходных PDF рисунки построены векторными объектами. Отдельный прогон сохранил четыре найденные панели D001 и шесть D014 в виде счётчиков, реальные границы выбранной панели и доказательство для каждой извлечённой точки. Выбор страницы, рисунка, панели и серии пока задаётся пользователем.

## Результаты

- **D001, PDF 8, Fig. 3(a).** Семь вершин, HotpotQA при anchors=1 → 0.528. Контрольная ошибка 0 при допуске 0.001. Обе шкалы автоматически считаны через PDFium.
- **D014, PDF 16, Figure 10.** Верхняя левая панель Wizard of Wikipedia / GPT-4o-mini. 231 маркер, 462 из 462 координат уложились в абсолютный допуск 0.0001. Максимальная абсолютная ошибка около 0.00005005. Для сверки сопоставлялся порядковый номер маркера внутри панели. Эталон не участвовал в извлечении.
- **P013, PDF 8, Figure 5.** В корпусе test это действительно скан с JPEG вместо текстового слоя. Тепловая карта слегка перекошена, часть надписей мелкая. На вырезке RapidOCR прочитал `RAG`, `BubbleRAG`, `Layer`, обе границы шкалы `0.0` и `0.002`, несколько делений и выдал лишние распознавания. OCR даёт основания для чтения подписей. Числа по цвету ещё не проверены. Для линейного растрового графика сначала нужен пример с различимой серией, затем проверка по координатам и ручной калибровке. Для тепловой карты нужна собственная калибровка цветовой шкалы с учётом сжатия.

Автообнаружение проверено на двух известных вёрстках с векторной рамкой, двумя осями с делениями и подписью ниже. D001 Figure 3(d) с наклонными подписями и нелинейной последовательностью делений не входит в числовую проверку. Типовой порядок для новой статьи пока не проверен. Серию и, для облака D014, диаметр маркера задаёт команда. При сомнительном числе код сохраняет замечание и область панели либо страницу. Ссылка открывает страницу. У координат области есть формат штатной карты PDF, пригодный для будущей подсветки в PDF.js.

## Воспроизведение

Из корня репозитория с окружением Python. Переменная `RAG_DEV_CORPUS` указывает на распакованный комплект с каталогами `dev`, `test` и `dev_gold`. Например, в основном чекауте:

```bash
export RAG_DEV_CORPUS="$HOME/Documents/RAG/docs/context/RAG_ВИНИТИ_участникам_2026-11-20"

python -m rag_mvp.plot_extract "$RAG_DEV_CORPUS/dev/D001.pdf" \
  --page 8 --figure 3 --panel a --series HotpotQA --strategy vector-line \
  --x-axis anchors --y-axis EM --out runs/plot-pilot/D001.json

python -m rag_mvp.plot_extract "$RAG_DEV_CORPUS/dev/D014.pdf" \
  --page 16 --figure 10 --panel 1 --series 'Wizard of Wikipedia / GPT-4o-mini' \
  --strategy vector-scatter --marker-size 1.494 \
  --x-axis 'Knowledge Precision' --y-axis 'Answer F1' --out runs/plot-pilot/D014.json

python -m unittest discover -s tests -p 'test_plot_extract.py' -v
```

Для отладки D001 можно добавить обе области: `--panel-box 70 70 192 176 --plot-box 104.463 84.251 191.944 153.06`. Значения делений при необходимости передаются через `--x-ticks 1 2 3 4 5 6 7 --y-ticks .575 .550 .525 .500`. Оси считаются слева направо и сверху вниз. Области указаны в пунктах PDF от верхнего левого угла.

## Растровый пилот и подсветка

В презентации ВИНИТИ требуется сохранить источник и место извлечения каждого значения. Эталон содержит 100 записей D013 из Figure 2 с PDF-страницы 9. Страница состоит из JPEG примерно 175 dpi, с перекосом и без слоя текста. Для первой проверки взяты десять измерений Exact Match серии PPO на панели (a). Эталон получен из исходной векторной версии, поэтому сравнение дополнительно измеряет потерю точности при переходе к скану. [Презентация, слайд 2](../context/ВИНИТИ+ЮФУ.pdf#page=2) · [Аудит D013](../context/RAG_ВИНИТИ_участникам_2026-11-20/dev_gold/coverage/D013_audit.json)

OpenCV выпрямляет панель по четырём вручную заданным углам и находит тёмную линию на заданных шагах. Калибровка использует видимые деления, размеченные вручную. RapidOCR на диагностической вырезке прочитал все девять числовых подписей осей. Его выход пока проверялся отдельно. Алгоритм извлёк 9 из 10 точек, 19.986% при шаге 50 против эталона 20.000%. При шаге 175 на позиции с близкими линиями алгоритм не нашёл однозначной тёмной отметки. Этот шаг попал в замечания без значения. Координаты точек возвращаются на исходную наклонённую страницу. Метод пригоден для первого контрольного графика с одной выделенной тёмной линией, сохраняющей контраст относительно другой серии.

Для векторной панели можно передать только `--panel-box`. Внутри исправленной области CLI сам ищет единственную рамку осей, сохраняет режим `corrected` и отказывается от выбора, если рамок несколько. Для отчёта добавьте `--preview runs/plot-pilot/D001.html` или другой путь.

```bash
python -m rag_mvp.plot_extract "$RAG_DEV_CORPUS/dev/D013.pdf" \
  --page 9 --figure 2 --panel a --series PPO --strategy raster-line \
  --x-axis step --y-axis EM \
  --raster-config .scratch/plot-extraction/d013-raster-config.json \
  --out runs/plot-pilot/D013.json --preview runs/plot-pilot/D013.html
```

Для скана нужен OpenCV из зависимостей RapidOCR. Ожидаемый код завершения D013 — 2, означающий сохранённый результат с замечанием. Откройте HTML-файл в браузере. Клик по `x=50` подсвечивает область на растровом представлении исходной страницы, отдельная ссылка открывает оригинал PDF. Проверено кликом в Chromium.

## Сравнение стратегий на одной панели

На D001, Fig. 3(a), PDF 8, одна и та же серия HotpotQA обработана тремя способами. Для растрового сравнения использован рендер той же PDF-страницы при 288 dpi. Рамка и деления взяты из автоматической калибровки векторного прогона. Значения серии из векторного прогона не передавались растровому. Для поиска видимых маркеров заданы диаметр 4.654 PDF-пункта и порог яркости 175 для растрового прогона. Все числа сверены по `anchors` с записями R310–R316 из `dev_gold/results.csv`.

| Стратегия D001 | Найдено | В допуске ±0.001 | Макс. ошибка среди найденных | Замечания |
| --- | --- | --- | --- | --- |
| Векторная линия | 7/7 | 7/7 | 0 | 0 |
| Центры векторных маркеров | 7/7 | 7/7 | 0 | 0 |
| Растровая линия | 6/7 | 6/7 | 0.000263 | `anchors=3`, четыре отклика в полосе поиска |

На JPEG-скане D013, Fig. 2(a), PDF 9, векторная стратегия выдала одно замечание со ссылкой на страницу. Растровая вернула 9/10 значений; 7/10 уложились в допуск ±0.001 на шкале долей, максимальная ошибка 0.001714. Шаг 175 попал в замечания. Две оценки вышли за допуск при сверке с эталоном, хотя алгоритм смог выделить линию. Это ограничение оценки уверенности. В обоих растровых прогонах замечание о неоднозначной точке содержит `sample_x` и область поиска на оригинальной странице. Клик по замечанию в локальном HTML подсвечивает именно эту полосу.

Для цифровой линии основной путь — векторные вершины. Векторные маркеры полезны как контроль и при отсутствии подходящей полилинии, если известны параметры маркера. Для JPEG в этом пилоте числовой выход есть только у растровой стратегии. При наличии замечания частичный результат сохраняется, CLI возвращает код 2.
