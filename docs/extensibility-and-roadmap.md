# Расширение платформы и Roadmap

Система спроектирована как **модульный конструктор** поверх неизменяемых сырых артефактов (`article-text.json`, `grid-*.json`) и единого ядра [`assemble()`](../rag_mvp/core/measurement_binding.py). Ниже — конкретные точки расширения и честный список того, что сознательно осталось за рамками текущего релиза.

## Как подключить новую стратегию (3 точки расширения)

### 1. Новый парсер текста, таблиц или графиков
- **Где:** [`rag_mvp/strategies/`](../rag_mvp/strategies/) — три независимых реестра:
  - текст: [`article_text_readers.py`](../rag_mvp/strategies/article_text_readers.py)
  - таблицы: [`table_readers.py`](../rag_mvp/strategies/table_readers.py)
  - графики: [`figure_readers.py`](../rag_mvp/strategies/figure_readers.py)
- **Контракт:** ридер возвращает только сырые фрагменты/ячейки/точки с координатами `box` в долях страницы PDF и `evidence_id`, не пытаясь придумывать семантику.
- **Автоматическая интеграция:** после регистрации в реестре стратегия сразу появляется в `./rag strategies`, `GET /api/strategies`, `./rag compare` и может выбираться явно в CLI и очереди RabbitMQ.

### 2. Новая стратегия привязки (правило, словарь или LLM/RAG-адаптер)
- **Где:** [`rag_mvp/article_context/`](../rag_mvp/article_context/) (для Уровня 1) или [`scripts/submission_passport.py`](../scripts/submission_passport.py) + [`experiments/entity-passport/`](../experiments/entity-passport/) (для Уровня 2).
- **Контракт ([ADR-0002](adr/0002-observation-assertion-assemble-core.md)):**
  1. На вход приходят уже сохранённые `grid-*.json` и `article-text.json` (повторный парсинг PDF не требуется).
  2. Стратегия формирует список `Assertion(field, value, Scope, evidence_ids)` — например, классифицирует роли шапок, достаёт `evaluation_protocol` из §4 или извлекает ключевые числа из прозы.
  3. Для LLM/RAG-стратегий ([ADR-0004](adr/0004-llm-and-vlm-integration-boundary.md)) перед передачей в `assemble()` обязателен детерминированный верификатор цитат: дословная цитата должна существовать внутри указанного `evidence_id`.
  4. `assemble()` сводит новые утверждения с существующими; конфликты автоматически попадают в `issues.csv`.

### 3. Обязательный контур проверки (4 гейта перед мерджем)
Любая новая стратегия принимается только при прохождении всех четырёх проверок:
1. **Unit и интеграционные тесты:** `bash qa/run_workers.sh`, `pnpm --dir web test:qa` и `tests/test_submission_passport.py`.
2. **Независимый эталон `dev_gold` (21 статья, 5 908 табличных строк):** `scripts/score-dev.py` — контроль отсутствия деградации Precision/Recall (текущий ориентир: Precision **89,23%**, Recall **33,23%**).
3. **Отрицательный контроль `P020 = 0`:** таблица описательной статистики не должна порождать ложных измерений качества.
4. **Официальный валидатор ВИНИТИ:** `check_submission.py <bundle> test` → строго **`Errors: 0`**.

## Что не вошло в текущий релиз (Roadmap)

1. **Сильная LLM + RAG поверх `article-text.json` (приоритет #1):**
   - Извлечение ключевых результатов из прозы (Abstract / §4 Experiments) для закрытия оставшихся ~5% статей корпуса без табличных результатов (`P016`, `P029`, `P034`).
   - Дозаполнение открытых контекстных полей (`dataset_id`, `evaluation_protocol`, `generator_model`, `task_id`, `metric_unit`), которые сейчас честно зафиксированы в `issues.csv`, через верифицированные `Assertion` ([ADR-0004](adr/0004-llm-and-vlm-integration-boundary.md)).
2. **Массовый графический конвейер:**
   - Сейчас векторное чтение работает в вебе на `D001 Figure 3(a)`, а на `test/` проведён аудит `chart-crop-probe` (6/6 напечатанных чисел у 4B VLM, но ошибки выбора оси и 0/6 по шкале без подписей).
   - Следующий шаг: геометрическая калибровка осей + голосование ансамбля VLM (`qwen-vision`, `granite-vision`, `paddleocr-vl`) с ручной проверкой спорных точек в интерфейсе.
3. **Перенос хранилища на PostgreSQL ([ADR-0001](adr/0001-pipeline-postgres-and-rabbitmq.md)):**
   - Замена SQLite на единый Postgres для многоворкерной оркестрации, сквозного SQL-поиска по всему корпусу и межстатейного сопоставления сопоставимых экспериментов.
4. **Точечный разбор склеенных ячеек и расширение цитат B3:**
   - Подключение `pdfplumber`-fallback для таблиц, где Docling склеил соседние строки (проверено локально на `P027 Table 2`: 12/12 значений; аналогично `P009 Table 3`, `P033 Table 3`).
   - Расширение `source_fragment` в слое B3 с короткого числа до полной строки таблицы с сохранением буквального совпадения в `check_submission.py`.
